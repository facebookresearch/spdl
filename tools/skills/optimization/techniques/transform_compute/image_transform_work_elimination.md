# Image transform work elimination

These techniques reduce discarded image work, geometric-transform cost and temporary storage. Open this topic when view selection, reprojection, CPU augmentation or whole-image scratch space dominates preparation.

[Catalog index](../../technique_catalog.md) · [Transform compute](../transform_compute.md)

**`select_view_and_fields_before_tensorize`: discard unused input before materializing it**
- Trigger: decoding and tensorization build views, fields, instances or masks that later transforms discard.
- Technique: trace the final sample's dependencies backward through the transform chain, including labels and calibration, then select the required view and fields before their expensive decode or tensor conversion. For example, if one of four camera views is selected, carry that view's image, calibration and labels forward rather than tensorizing all four and dropping three. Keep retained boolean masks boolean. This removes allocation and augmentation work, not just bytes from the final batch.
- Guards: preserve retained-input RNG consumption, labels, calibration and optional-field behavior. If view selection is random, make the same choice with the same logical sample identity before moving it earlier; discarded transforms may still have consumed RNG used later. Prove equivalence against the complete old transform chain; a smaller payload is not a win if it changes the sample. Attribute timing carefully: in one comparison the view-selection speedup was measured together with other changes, so it does not isolate this technique.

**`lower_resolution_forward_preprocessing`: simplify expensive geometric input transforms**
- Trigger: dense high-resolution reprojection dominates input CPU while GPUs wait for samples. Reprojection uses image values, depth and calibration to map source pixels into another camera or image grid; dense grids require many projected locations and temporary values.
- Technique: precompute geometry that depends only on fixed calibration, such as a lookup table of epipolar candidates or camera rays, and reuse it across samples instead of recomputing it with per-sample depth and image values. Run the reprojection on a smaller target grid, for example a fraction of the full image resolution, to reduce the number of output locations and temporary values processed. When depth is sparse, fill its holes at the depth sensor's own resolution first and then forward-project it into the smaller target grid. Check the projection direction against ground truth: a fast backward projection can be visibly misaligned where forward projection matches. Moving suitable pixel-parallel input transforms to the device is a separate change; adopt it only after measuring the resulting stage balance, and attribute its gain separately from other pipeline changes made with it. The grid size, projection direction and hole-filling policy are workload choices; a measured speedup does not determine them.
- Guards: this can change the representation rather than preserve numerical equivalence. Reducing a depth grid before projection is not generally equivalent to projecting at full resolution and resizing afterward: depth discontinuities can select different surfaces. Hole-filling turns sparse depth into semi-dense depth, which changes the model's input distribution. Validate alignment, depth (z) bias, interpolation, holes and downstream model quality; precomputed lookup tables can introduce misalignment or z bias, and visual comparison or a single downstream run is not a quantitative quality validation. Invalidate reusable geometry when calibration changes. Do not treat a faster transform as an accepted representation change or promote it on timing alone.

**`lean_cpu_augmentation`: keep CPU augmentation compact and vectorized**
- Trigger: CPU augmentation spends substantial time in generic tensor or module dispatch for simple image operations.
- Technique: keep decoded images as uint8 while applying photometric operations that have an equivalent 256-entry lookup table, use native array routines instead of per-pixel Python or repeated module dispatch, and convert/scale to the consumer's floating dtype once at the end. For example, a fixed brightness operation can map every byte through a table computed with the baseline's clipping and rounding rule; applying two quantized tables is not automatically equivalent to two floating-point transforms followed by one final quantization. Skip resizing or cropping only when the calculated operation is genuinely an identity.
- Guards: validate interpolation, pixels, dtype and random-choice semantics against the baseline. A faster alternative library or arithmetic order can change outputs; test trained quality where exact parity is unavailable. Avoid changing the effective augmentation policy just to reduce work.

**`blockwise_transform_temporaries`: cap scratch space for image transforms**
- Trigger: whole-image temporaries and page faults dominate input-transform CPU and memory.
- Technique: allocate final image/mask outputs once and evaluate the transform on bounded row blocks, reusing scratch for each block instead of creating whole-image intermediate arrays. Write each block's result to its final slice. Include neighboring input rows when an operation needs a halo—the extra input rows needed to compute a block's boundary pixels correctly; defer reductions that truly require the complete image until block processing finishes. This bounds intermediate storage and reduces allocation/page-fault work without discarding pixels.
- Guards: preserve exact pixels, masks and reduction order. Independently normalizing each block is not equivalent to whole-image normalization; block-local calculations must use the same global parameters. Validate the target BLAS build and thread settings, since layout and arithmetic can change across them. Bound scratch across all concurrent views and workers; an isolated warm-transform win is not itself a training win.

**`resize_and_cap_before_expansion`: apply intended limits before creating discarded data**
- Trigger: upscaling, tiling or other expansion materializes pixels or media that a later stage discards.
- Technique: trace the final retained media set and target geometry, then push each existing limit to the earliest stage that can still produce the same output. For example, if a deterministic selection keeps the first two of eight images, select those same two before tiling rather than tile all eight and discard six. Avoid creating pixels or media outside the retained input. Move a resize earlier only when its relation to expansion is understood; resizing each crop is not generally equivalent to resizing the full image and then cropping.
- Guards: preserve cropping, calibration and RNG semantics, including choices for retained inputs that previously followed discarded work. A smaller sample or a new media cap is a representation change, not free equivalence; validate quality and coverage. Attribute cap-only effects separately from a reordered or redesigned transform stack.
