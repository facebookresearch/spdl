# Input encoder reuse and packing

These techniques reuse stable or causal input-encoder work and remove independent-sequence padding. Open this topic when repeated encoding, overlapping context or padded inputs dominate preparation, while preserving the encoder and sample contracts.

[Catalog index](../../technique_catalog.md) · [Transform compute](../transform_compute.md)

**`offline_pretokenization`: move stable input encoding out of training**
- Trigger: each training visit runs model-based tokenization or input encoding on the raw sample. Repeated encoder work, or variable work per sample, delays data delivery and can leave ranks waiting for the slowest input path even when the encoding contract has not changed.
- Technique: precompute tokens or encoded inputs for each logical sample when the tokenizer and preprocessing contract are stable. Store those outputs with their sample identities and versioned dataset contract, then load the materialized representation instead of invoking the encoder during training. Reuse only the stable encoding: any required per-visit stochastic behavior must still occur with its original semantics. This moves encoding to a preparation pass and permits reuse; it does not remove its cost or justify changing what the encoder produces.
- Guards: version the encoder, preprocessing configuration and output schema with the dataset. Preserve row identity, order, coverage and required stochastic behavior. This is impractical during rapid tokenizer iteration; compare total preprocessing-plus-training cost, storage growth and reuse rather than treating offline work as free.

**`stateful_chunk_encoding`: reuse causal encoder context across input chunks**
- Trigger: a long input is encoded in chunks that overlap to provide left context, so the encoder repeatedly processes positions already seen in the preceding chunk. A causal encoder uses earlier positions, not future ones; only an encoder with a supported cached-execution contract can reuse that work safely.
- Technique: feed only the new portion of each chunk and carry the encoder's per-layer key/value cache into the next call. That cache retains attention state for previously encoded positions; emit outputs for the new positions rather than emitting the overlap again. Evict context beyond the required receptive field when the encoder's cache contract supports it. Reusing cached left context avoids encoding the same input repeatedly; it is not merely concatenating independently encoded chunk outputs.
- Guards: bound state and reset it at sample boundaries. Validate context truncation, positional encoding and downstream loss or quality: positional resets can make outputs non-bit-exact, and trimming a full-context cache changes its contract. Do not substitute cached execution for a bidirectional encoder whose contract requires future context.

**`sequence_packing_with_segment_isolation`: pack independent inputs without cross-segment leakage**
- Trigger: padding independent documents wastes input-encoder work.
- Technique: concatenate token sequences into a packed buffer with segment boundaries, using only an encoder that supports the same independent-sequence contract in packed form. For documents of lengths 3 and 2, five packed tokens replace two rows padded to length 3, but tokens in the second segment must not attend to the first. Supply segment-isolated attention (and within-segment causal masking where required), the baseline position indices, end markers and per-segment pooling. Track original document IDs so pooled or token-level outputs can be unpacked in original order. Concatenation without those boundaries changes the encoder task rather than just removing padding.
- Guards: preserve effective batch size, negatives and batch rounding; five packed tokens still represent two documents, not one example. Do not substitute the number of packs for the number of independent examples in loss normalization. A framework's implicit packing (position indices without an explicit isolation mask) may not isolate segments; compare packed against padded outputs, and budget for a dense block-diagonal mask, whose memory grows with the square of the packed length. In BF16, outputs depend on batch composition and reduction order even without packing, so pin the batch size when checking bit-exact parity. Matching outputs at a fixed batch do not establish training equivalence: packed and padded training can follow slightly different trajectories and lose quality on individual metrics, such as top-k recall on one evaluation set, while other metrics match. Validate final task quality on every evaluation set, with every evaluation completed for both arms, and investigate a persistent single-metric gap before promoting. The speedup shrinks when other inputs, such as hard negatives, stay padded. Do not promote until the quality and effective-batch gates pass.
