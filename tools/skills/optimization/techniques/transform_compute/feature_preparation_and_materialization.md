# Feature preparation and materialization

These techniques reduce repeated feature traversal, parsing, dispatch and materialization. Open this topic when small feature operations, temporary allocations, DataFrame decoding or expanded metadata dominate row preparation.

[Catalog index](../../technique_catalog.md) · [Transform compute](../transform_compute.md)

**`fused_per_feature_preproc_pass`: amortize small feature operations in one pass**
- Trigger: a row's decoded feature values pass through separate small bucketing, hashing or normalization operations. Repeated operator dispatch, traversal and intermediate allocation can cost more than the arithmetic on each value.
- Technique: combine compatible feature operations into one row- or batch-level traversal. Read each decoded value once, apply its required operations in the baseline order, and write the corresponding feature outputs into their final storage rather than dispatching separate operators and retaining intermediate arrays. Reuse a computed value only where the operations actually share it; fusion does not make different hash or normalization formulas interchangeable.
- Guards: preserve hash, bucket-boundary, null and normalization semantics. Measure CPU or worker-resource savings separately from training throughput; a GPU-bound consumer may remain unchanged. Confirm the active implementation has actually reached the benchmark process.

**`parse_shared_fields_once`: share metadata parsing across targets**
- Trigger: several labels or prediction targets read the same row metadata, but each target decodes or parses it independently. The repeated work constructs identical shared values before target-specific processing even begins.
- Technique: collect the fields required by all active targets, including fields used to derive their inputs, and parse each shared value once per row. Pass that parsed representation to each target's existing processing. For example, two target builders that both parse the same annotation field can share its parsed contents while still applying their own selection and default rules. This removes duplicate parsing, not either target's output or distinct logic.
- Guards: include the full dependency closure and preserve target-specific defaults, missing-field handling and error behavior. Scope reuse to the row unless immutability and lifetime permit broader sharing; do not expose mutable parsed state to concurrent consumers.

**`allocation_free_preproc_loops`: remove transient allocations and repeated copying**
- Trigger: preprocessing profiles show temporary tensors or vectors, deep copies to inspect one value, or exact-size growth on every append. Repeated allocation and copying move already available values instead of advancing the transform.
- Technique: construct small flags or masks in the existing loop, read values in place instead of copying their container to inspect them, and reuse bounded scratch buffers. Retain geometric capacity growth rather than repeated `reserve(size()+n)`: reserving only enough for each append can repeatedly copy the entire accumulated prefix, producing quadratic total copying. Keep the final output allocation and any copy needed for independent ownership; the target is avoidable temporary work, not every allocation regardless of lifetime.
- Guards: do not recycle storage while downstream views retain it. Preserve dtype, masking and exception semantics; initialize every exposed output element. Bound retained capacity for unusually large samples rather than turning allocation savings into unbounded memory retention.

**`gil_releasing_dataframe_decode`: compare decoding backends when threads stop scaling**
- Trigger: a threaded loader downloads per-row Parquet payloads, decodes DataFrames and extracts features, but uses only a fraction of its available CPU cores. Python's global interpreter lock (GIL) can serialize Python work even with many loader threads; resource use alone does not isolate the lock-holding stage.
- Technique: compare a compatible native DataFrame decoding backend while keeping the downloaded inputs, feature extraction, batching and runner configuration fixed. In one comparison, replacing the pandas backend with polars improved threaded loader throughput and CPU use. The likely explanation was that polars releases the GIL more during decode, but that was inferred, not measured directly. Check that the replacement preserves the required rows, columns, dtypes and logical conversions.
- Guards: measure actual parallelism rather than assuming every native decoder releases the GIL. In that comparison thread scaling remained partial and process workers remained faster; faster decoding helps less when downloads dominate. It measured cold download plus decode and data loading only, with no cache or model step, so it does not validate warm decoding or full training. Check interpreter-specific wheel availability: polars on a free-threaded Python build could not be tested there. Count total CPU and memory, retain cold-download outliers, and do not increase thread count blindly: higher thread concurrency can regress throughput, as one trial did.

**`bypass_empty_or_identity_stages`: omit work whose result is already available**
- Trigger: an empty stage configuration, all-true mask or identity geometry still pays dispatch, validation, gathering or expansion cost.
- Technique: select a direct input path at construction for genuinely empty stage lists. Add inexpensive identity predicates where an unchanged sample can safely bypass a redundant operation. For example, an all-true selection mask may permit returning the existing values instead of gathering them into a new array, but only when the consumer allows that alias. Keep the normal path for nonidentity inputs; skipping an operation is valid only when its result and required side effects are already satisfied.
- Guards: retain optional-stage behavior, random target selection, aliases and fallback paths. A predicate must cost less than the avoided work. Identity geometry is not permission to skip random choices that affect later transforms.

**`offset_only_nonempty_mask`: test string emptiness without scanning payloads**
- Trigger: filtering large string columns scans character data solely to decide whether each value is empty.
- Technique: for a string column stored as payload bytes, row-boundary offsets and a validity bitmap, test whether each row's end offset exceeds its start offset. Combine this with validity according to the baseline's null policy. For example, offsets [0, 2, 2, 3] and validity [true, true, false] yield [true, false, false] when selecting valid nonempty rows; the third row's reserved byte does not make a null value nonempty. Reading only offsets and validity avoids scanning the much larger character payload.
- Guards: use this only for emptiness, not character count, whitespace or content predicates. Validate offset width, null semantics and sliced-column boundaries; a slice may start at a nonzero offset and validity-bit position. Preserve nullable predicate outputs if the baseline retains nulls rather than excluding them. Require identical masks before replacing the payload-scanning path.

**`offsets_only_sparse_normalization`: keep sparse metadata packed through normalization**
- Trigger: sparse-feature preprocessing repeatedly constructs ranges and casts offsets for each feature.
- Technique: represent variable-length feature rows as a flat values buffer plus boundary offsets, and let a compatible implementation of the same normalization read row spans or lengths directly from those offsets. For example, offsets [0, 2, 2, 5] describe three rows with lengths 2, 0 and 3 over five values; the repeated boundary preserves the empty middle row. Carry the packed representation through compatible consumers instead of expanding an index range for each feature and recasting it repeatedly. Construct explicit ranges only for consumers that actually require them; this changes metadata handling, not the normalization formula.
- Guards: preserve empty-feature and final-row semantics, offset widths and consumer dtype requirements. Retain the ranged fallback where packed offsets are unsupported. Validate coverage and output equivalence before interpreting reduced synchronization as a gain.
